Nested-call support uses root/active/link fields in every promise
(12 bytes on ARM). blink now awaits blink_once, whose storage lives inside
blink_frame. The child uses the same blinker job and does not add another node.
Root link stores the job context; child link stores the parent continuation.
Scheduler dispatch uses the singleton; its removed bookkeeping saved16 bytes.
Removing node.owner saved4 bytes per job. Compact flags and one ready/timer
link saved another12 bytes per job. The compact change adds52/60 bytes Os
flash (M0/M3) versus the preceding node48 layout, including guarded IRQ flags.

ARM node36 layout (offset:size):
queue_next 0:4, pending_next 4:4, pending_prev 8:4, delta 12:4,
status 16:1, in_ready 17:1, in_timer 18:1, irq flags 19:1,
task 20:4, resume 24:4, done 28:4, result/wait union 32:4.
Ready/timer flags are thread-only byte fields. The separate IRQ byte contains
in_pending/token/accepts_signals/wake_requested and is accessed under the port critical guard.
